# km 项目知识库技能

km 根据项目代码和原有文档，生成可追溯的中文 Markdown 文档库、JSON 术语卡与有据工程图。源码或文档变化后，再次调用同一技能，更新受影响内容。

当前实现对应 v0.1.0 设计基线，发布候选与任务状态见 [CHANGELOG](CHANGELOG.md) 和 [任务总账](docs/devel/task/index.json)。

## 使用

将本目录作为名为 `km` 的技能载入宿主。在支持显式技能调用的宿主中，在目标工程调用：

```text
$km
```

首次调用不需要配置。也可以在请求中指定目标工程和范围。`/km` 是否可用取决于宿主的命令适配；本项目没有独立注册 slash command，当前未实测该入口。

默认输出：

```text
docs/official/
  README.md
  系统总体设计.md       # 按项目实际内容选择
  任务调度设计.md       # 示例：每个识别出的业务模块都有独立主设计
  任务调度-状态流转.md  # 示例：模块复杂细节按需拆专题
  任务分派流程.md       # 示例：复杂跨模块流程独立说明
  配置参考.md
  术语表.md
  .cards/
    k_<uuid>.json
    manifest.json
    last_attempt.json
    diagrams/d_<uuid>.json
```

图稿放在 `docs/assets/km/*.svg`，文章通过相对路径引用；每图语义清单在 `.cards/diagrams/`。

文档使用中文语义名称，不加排序数字。卡片解释专业术语、缩写和项目独有名称，分别保留 `definition` 与 `project_usage`，可以关联多篇文章。核实批次、时间和实际取得的哈希集中在 manifest。

## 工作方式

宿主 AI 先理解全局架构，再按专题阅读原始资料并编写候选，最后统一检查和交付。单篇首次编写经过分析、起草与来源核对、表达修订、事实回查；更新先比对受影响结论，只修变更段落及必要上下文。无实质变化且证据可靠时保留原文和内容日期。

所有识别出的业务模块都独立成文，简单模块也保留主设计。复杂模块采用主设计加按需专题；总体保留主干协作、全局约束和逐模块摘要与链接，复杂跨模块流程单独说明，各模块展开自身职责并互链。模块按实际职责与契约识别，覆盖检查同时核对识别范围和主设计/必要专题的完整集合，不能仅凭文件存在声明已覆盖。

工程图先从原始来源生成并核对语义清单，再绘图，最后核对正文与实际渲染。按模块协作、复杂交互与业务状态触发必需图，并由 AI 按需补充；同图共享，不同视角另画，实现与目标分图。正式图稿须实际检查 Markdown 内嵌和独立 SVG。缺少必需的预览能力时如实待续；选配图可在修复全部引用、确保正文完整并通过整库检查后暂缓。

输出不作为下一轮的独立项目事实来源。覆盖不足时保留候选和待续记录；发现输出文件占用或外部修改时停止正式替换并报告。下次调用先核对未完成记录与实际文件，再继续处理。

默认使用当前项目和中文正文。需要限定范围时，可在 `docs/official/.cards/config.json` 中设置受支持的偏好，字段见[状态参考](references/library-state.md)。不需要为首次使用创建该文件。

## 技能组成

分发所需的执行资源只有：

| 资源 | 职责 |
|---|---|
| [SKILL.md](SKILL.md) | 技能名、触发范围、输出边界与资源入口 |
| [workflow.yaml](workflow.yaml) | 英文阶段说明、完成条件和失败去向 |
| [assets/diagrams/base.svg](assets/diagrams/base.svg) | 静态 SVG 基础模板 |
| [references/](references/) | 按需加载的写作、单篇流程、表达修订、术语及状态契约 |

制图采用本地英文参考与八类图型规则；出处和 MIT 声明见[上游说明](references/diagrams/upstream-notice.md)。manifest/尝试协议为 `2.0`，图稿语义清单为 `1.0`；当前不提供旧库迁移。

km 不依赖运行脚本、工作流引擎、模型 API Key 或网站框架。现有 `scripts/adflow-verify` 是维护本项目的治理工具，不是 km 的运行依赖。

## 验证与限制

开发检查包括技能基础格式、YAML/JSON 解析、参考路由和治理检查。T01 的 12 个历史样例见[初版验收记录](tests/acceptance.md)，T02 的 7 个模块分层样例见[分层验收记录](tests/module-docs.md)，T03 的八类图、双阅读环境及更新/失败场景见[工程制图记录](tests/diagrams.md)。这些均为同会话演练和文件核对，不能代替独立宿主触发测试或完整模块发现保证。

当前未验证已安装宿主中的 `$km` 发现与触发、`/km` 注册、大型工程或并发修改。T03 的实际写入中断仅覆盖前向引用断言失败后的记录与续跑，未覆盖文件系统故障。不会把静态代码阅读写成业务运行或生产验收结论。多文件替换没有事务或自动回滚保证。

研发规则、设计与任务记录由[文档中心](docs/README.md)导航。对表达修订规则的参考来源固定到上游提交，见[英文参考的出处](references/technical-editing.md#provenance)。
