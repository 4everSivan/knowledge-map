# km v0.1 验收说明

> **created**: 2026-10-15 ｜ **last-change**: 2026-10-16 ｜ **status**: active

## 范围与方法

本页保留 T01 在模块分层约束新增前的初版验收事实；不将这些历史样例视为已经通过后续的全部模块覆盖要求。新增规则由 T02 单独演练，见[业务模块分层验收](module-docs.md)。

T03 将 manifest/尝试/workflow 协议扩展为 2.0，图稿相关证据见[工程制图验收](diagrams.md)。本页历史的 1.0 状态文件不是新协议的验收证据，也不作为旧库迁移实现。

本轮由当前会话阅读实际技能与 workflow，在隔离样例上执行取证、生成候选、修订与检查。JSON/YAML 解析、文件哈希及范围比较由宿主现有 Python 工具完成；没有新增测试脚本或 km 校验程序，也没有启动 subagents 或第二个模型会话。

因此下表是同会话流程演练及产物核对结果，不是独立测试者的前向执行，也不是技能自动发现、slash command 或生产环境验收。任务为 T01，发布批次为 v0.1.0，治理验收批次为 `local-20261015`。原始样例记录的批次标识 `km-v0.1-20261015` 保留为对应来源；调整批次命名不表示重新执行了样例。

## 样例

主样例 RetryDesk 位于 `local/acceptance/km-v0.1/target/`。其实际资料包含：

| 资料 | 含义 |
|---|---|
| `settings.py` | 默认 `enabled=False`、最大尝试次数初始为 30 |
| `jobs.py` | 未启用返回 skipped；启用后有限次调用回调，真值提前完成，耗尽返回 exhausted；不捕获回调异常 |
| `runner.py` | main 调用执行器，显式启用；没有运行该业务入口 |
| `legacy.py` | 未接入主链路的 OldHook 类型 |
| 原 README | AttemptBudget 的定义、状态含义及入口声明 |
| 原 design.md | 未来目标，不能作为已实现能力 |

初次产物为四篇中文 Markdown 和一张术语卡。随后按场景实际改变来源和输出；每个检查点比较当时的真实文件。`initial-snapshot.json`、`confirmed-snapshot.json` 和 `results.json` 保存在该批次目录，作为本机过程证据，不分发给技能使用项目。

另有受控的单功能样例 `retirement-target/`：将唯一实现来源移出目标范围，核对过期；再由原项目文档明确移除唯一功能，形成保留身份和历史出处的退役候选。被移出的源文件仍保存在批次目录，没有清理原始材料。

## 本轮结果

| 场景 | 实际结果 | 证据边界 |
|---|---|---|
| 首次生成 | 通过：4 篇中文文档、1 张卡，实际入口与未来目标区分，文章锚点存在 | 静态阅读与宿主文件检查，未运行业务程序 |
| 无变化复用 | 通过：6 个来源与 5 个内容文件哈希相同；正文、日期和 manifest 字节不变 | 仅刷新 last_attempt；不依赖提交号 |
| 默认值更新 | 通过：30 改为 10，追踪默认值消费者，只改两处正文与卡片用途 | 保留卡片 ID、定义、启用条件和无关文章字节 |
| 仅原文档目标变化 | 通过：目标改为持久化，仍明确尚未实现，Python 来源哈希不变 | 不把文档声明转成实现结论 |
| 有据术语改名 | 通过：原文档给出旧称，AttemptQuota 继续沿用原 ID | 保留明确文章锚点，别名有原始依据 |
| 部分覆盖保护 | 通过：保留 Markdown 候选，正式集合及 manifest 字节不变 | 人为中止专题以演练 partial，不是工具崩溃 |
| 部分覆盖续读 | 通过：待续范围阻止短路，实际重读并比较全部 6 个来源 | 相同来源继续复用正文 |
| 无效文章绑定 | 通过：缺失锚点被识别，错误卡片仅保留为 JSON 候选 | 检查真实目标文件，正式卡片未替换 |
| 表达修订事实回查 | 通过：拒绝删去启用条件、上限及提前完成条件的候选 | 同会话依据真实分支作语义判断，不是自动语义证明 |
| 外部修改保护 | 通过：改动文件逐字节保留，其他内容及 manifest 不变 | 末次尝试按预期为 failed、published=false |
| 来源不可用 | 通过：实际移出实现来源，保留文档声明时形成 stale 候选 | 不能仅凭单个文件消失判定退役 |
| 已确认退役 | 通过：受控样例明确移除唯一功能后形成 retired 候选 | 仅验证专题候选，未宣称完整知识库发布 |

技能基础检查与 YAML 解析不是同一种检查。首次 YAML 解析发现篇首块文本缺少缩进，修正后解析通过；不能以技能 frontmatter 检查代替 workflow 解析。

## 复跑与尚未验证范围

复跑时在新的 `local/` 批次目录创建上述最小资料，按实际 workflow 顺序执行，重新取得 run ID、时间、哈希及检查结果。不要复用本轮通过记录，也不要把直接生成预期答案称作独立模型验证。测试完成后不自动清理既有运行资料。

维护本项目可执行：

```sh
scripts/adflow-verify --mode init --json
scripts/adflow-verify --json
```

技能基础检查使用当前环境 skill-creator 提供的 `quick_validate.py`；YAML 解析使用本机已有 PyYAML。它们是开发检查工具，不是目标项目调用 km 的依赖。

尚未验证：安装后宿主中的 `$km` 发现与触发、`/km` 适配、大型工程、并发写入、真实多文件写入中断恢复，以及复杂工程的来源删除与退役。上述限制不以表中的 12 个样例覆盖替代。当前没有业务程序或目标环境运行证据。
