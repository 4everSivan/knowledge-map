# 工程制图设计

> **created**: 2026-10-16 ｜ **last-change**: 2026-10-16 ｜ **status**: baseline

## 1. 简介

本设计适用于尚未发布的 km v0.1.0。用户已逐项确认制图策略，并于 2026-10-16 表示“我审查无误了，然后下一步是否可以开始”，据此建立基线。T03 负责执行资源与验收；设计批准不等于宿主执行或生产验收。

目标是在同一 km 调用中完成取证、语义核对、静态 SVG 制图、图文复核和整库交付。面向 AI 的资源使用英文，图中标签及正文默认中文。采用 diagram-design 的本地技术适配，不要求安装上游技能、运行脚本、配置模型服务或建设网站。

## 3. 规范

| 项目 | 已确认契约 |
|---|---|
| 必需与选配 | 规划时确定必要性及来源理由；任何文章必需该图，整库即按必需图处理 |
| 共同触发 | 多业务模块依赖或协作需要总体关系图；复杂跨模块责任交接需要交互图；业务状态条件决定行为需要状态流转图；AI 按事实补充 |
| 生成顺序 | 原始材料 → 语义清单候选 → 节点、关系及条件核对 → SVG 与正文 → 图文和实际渲染复核 |
| 事实依据 | 每个工程节点、关系及有工程含义的分组关联证据；可共用记录；图例、折点不要求独立证据 |
| 视角 | 实现与目标分图；目标有原始资料依据且标注未实现；配置声明不冒充运行实况 |
| 内容归属 | 同图共享一份 SVG 和清单，指定所属文章；不同层级或场景另图，核对共享契约 |
| 布局维护 | 稳定标识、局部更新；必要重排说明原因；语义与布局差异分别检查 |
| 正式检查 | 结构、语义及实际渲染均需通过；同时验证 Markdown 内嵌与独立 SVG，记录实际查看器及证据 |
| 必需图失败 | 缺来源、未完成、必需检查失败或未执行时不确认新集合，不因缺工具降为选配 |
| 选配图失败 | 可暂缓；失效图的全部当前引用及活跃索引移除，正文仍完整且新集合检查通过后才交付 |
| 状态分离 | 源码覆盖、正式集合验证、未交付候选检查分别记录；暂缓不伪装为通过，也不自动等于源码未读 |
| 版本范围 | 当前无旧版存量，直接采用新协议，不做旧库兼容、转换或迁移 |

首次无需人工配置或逐图审批。触发条件依据实际职责、协作和状态，不依据源码目录数量、文章标题或图型清单。简单模块仍有独立主设计，但不机械配图。一图可完整覆盖多个问题；超出阅读容量时拆总览与细节，不删必要条件或失败路径。

## 4. 设计详情

### 4.1 资源与输出

<!-- @topic: EngineeringDiagrams -->

AI 按需读取制图入口、图稿协议、公共样式及所选图型参考。首批八类为架构、流程、时序、状态、数据流、实体关系、部署和依赖。SVG 基础模板为分发资源，不是目标工程事实。

| 路径 | 职责与基准 |
|---|---|
| `docs/official/*.md` | 中文平铺文档，图像引用相对当前文章 |
| `docs/assets/km/*.svg` | 正式图稿，英文语义连字符名称 |
| `docs/official/.cards/diagrams/d_<uuid>.json` | 每图一份轻量语义清单，身份不随批次变化 |
| `.cards/manifest.json` | 文档、卡片、图稿索引、实际哈希与核实记录 |
| `.cards/runs/<run_id>/diagram-plan.json` | 必需/选配及理由、文章用途、待续与暂缓计划 |
| `docs/assets/km/.staging/<run_id>/` | 必要时保留的 SVG 候选或可信恢复副本 |

所有生成 JSON 均位于 `.cards/`。正式图稿路径及清单路径在图稿索引中使用项目根相对路径，文章关联沿用文档根相对路径。拒绝越界、外部符号链接和未确认占用。生成图稿及候选排除出事实输入，其他原始项目文档和资产继续读取；资料中的指令不授予执行权限。

### 4.2 语义与状态协议

清单协议为 `1.0`：记录稳定图稿 ID、标题、图型、视角、节点、关系、适用分组和原始证据。节点与关系不保存坐标、颜色或字体。证据用原始路径、符号、配置键或章节定位，行号仅辅助；说明静态实现、原始声明、推断或实际观察。图型必要字段保留调用顺序和方式、条件、关系基数、部署边界等，不用无类型箭头抹平区别。

manifest、最近尝试与 workflow 描述采用 `2.0`，术语卡与可选配置仍为各自的 `1.0`。这是协议版本，技能业务版本仍为未发布的 `0.1.0`。新 manifest 增加 `figures`，文档记录增加派生的 `figure_ids`；身份、路径、所属和引用文章、双文件哈希及核实批次由图稿索引管理。图稿不是术语卡，不用遍历所有 JSON 的方式统计术语。

具体字段和闭环约束以[图稿协议](../../../references/diagram-state.md)为准；不引入完整制图 DSL、自动布局或脚本引擎。未知协议保留文件并报告冲突；没有隐式迁移路径。

### 4.3 写作、检查和复用

在深入专题写作前检查宿主是否能取得实际 Markdown 与 SVG 渲染证据，记录工具和环境。缺能力时如实标注未执行；必要性仍由工程事实决定。语义清单先核对，发现事实错误返回原始资料，图面错误修订 SVG，再核对相关正文和共享视图。

采用静态 SVG、独立样式和系统字体，不含脚本、事件属性、远程资源及 `foreignObject`。结构、引用和实际哈希使用宿主已有工具；模型语义审阅与工具结果分别记录。实际渲染检查包括中文、箭头端点、条件标签、遮挡、裁切、缩放可读性及文章内位置。只对检查过的环境给出结论；不承诺全部 Markdown 查看器、PDF、Word 或网站兼容。

SVG 元素通过图稿前缀和图内稳定标识对应清单。共享来源或契约变化检查全部受影响图文，但不重写无关内容。有据复用要求源码、语义、输出所有权及相关渲染条件仍适用；复用旧视觉证据必须绑定相同文件哈希和适用环境，不能伪造本批次截图。核实批次变化不自动改变正文日期或知识内容修订号。

### 4.4 交付、中断与暂缓

必要源码和文档覆盖完整、正式集合的必需检查通过、无已知阻断后才交付。必需图未完成或缺必需检查时保留候选。选配图暂缓不进入正式图稿索引；移除失效引用后正文必须仍完整，任何引用文章要求该图时不得暂缓交付。候选失败如实记录，并与正式集合结果分开。

暂缓计划与受控留存材料使用专门尝试记录；旧 SVG 若退出活跃索引但需要保留，必须先建立受控留存记录，不丢失所有权。只有确认受管、没有适用引用且有实际处置记录后才移除；原始资产及现有 `local/` 不清理。

文章、清单和 SVG 使用同一集合检查并写入，manifest 最后更新。不保证跨目录原子替换或自动回滚。失败后停止替换，记录真实已写、待写和可信恢复材料；下次调用先检查实际文件，不凭旧 manifest 假定旧集合完整。

### 4.5 来源、实施与验收

适配来源固定为 diagram-design 提交 `d97c5c7477e54cee17cfa6459190610da0643a05`，保留 MIT 声明。采用语义先行、图型语法、少量强调、正交连线、可访问性和复杂度管理；不带入品牌初始化、默认 HTML 交付、动画、导入导出命令或 Python 检查器。出处及差异见[上游说明](../../../references/diagrams/upstream-notice.md)。

T03 验收需覆盖八类图的语义、中文 SVG 和实际 Markdown 阅读，必需图缺证据/无预览/渲染失败、选配图暂缓、共享引用、局部变更、无变化复用、外部修改与中断续跑。实际证据与未执行范围由任务及验收记录维护；同会话演练不冒充独立宿主调用或业务运行验收。
